# 戦闘後の経験値の計算

## 概要

通常の敵1体から得られる経験値は、敵ごとに設定された基礎経験値 `B` と敵レベル `L` で
決まります。

```text
特殊扱いの敵、または B > 100:
    経験値 = B

B <= 80:
    経験値 = floor(B * L * L / 500 + B / 20 + L)

81 <= B <= 100:
    経験値 = floor(B * L * L / 10 + B / 10 + L)
```

戦闘時間は、この式に使われません。戦闘結果の合計処理にも経過秒数を直接加算する処理は
ありません。そのため、同じ敵構成、同じ敵レベル、同じ補正という条件で「戦闘を長引かせる
だけで経験値が増える」とは結論づけられません。

一方、長い戦闘では攻撃や妖術などの有効な戦闘イベントが多くなりやすく、さすらい玉が
まだ出ていなければ、その出現抽選を受ける機会が増えます。経験値のさすらい玉を取った場合、
通常経験値と戦闘内イベント経験値を足した小計が2倍または3倍になります。ただし、これは
出現までの抽選機会が増える仕組みであり、戦闘時間に応じて経験値そのものが増える仕組みでは
ありません。さすらい玉は、1戦中に一度種類が決まると再抽選されません。

おはらいを一度も行わない戦闘でも経験値が増える場合があるため、おはらいは長期戦による
増加の必要条件ではありません。おはらい回数を経験値のさすらい玉へ使う処理もありません。
同じ条件にそろえた長期戦で残る経験値差の原因は、現在確認できている処理だけでは特定できません。

### ボー坊の経験値が多い理由

ボー坊の基礎経験値は `B = 81` です。通常妖怪の多くが入る `B <= 80` の式ではなく、
分母が500から10へ変わる高経験値側の式に入るため、レベルが上がると経験値が急増します。

| 敵レベル | ボー坊1体 | 同じレベルのボー坊3体 |
| ---: | ---: | ---: |
| 20 | 3,268 | 9,804 |
| 40 | 13,008 | 39,024 |
| 60 | 29,228 | 87,684 |
| 80 | 51,928 | 155,784 |

これは、さすらい玉や味方側の経験値補正を加える前の通常経験値です。1回の戦闘に出る
ボー坊が1体なら左列、3体なら右列が通常経験値の小計になります。

## 内部処理

### 通常経験値

敵1体分の経験値を計算する関数は `sub_55549C` です。

| 役割 | 仮想アドレス | `code.bin`オフセット |
| --- | ---: | ---: |
| 敵1体分の経験値計算 | `0x55549C` | `0x45549C` |
| 基礎経験値の読出し | `0x550F9C` | `0x450F9C` |
| 通常の敵6枠からの呼出し | `0x550FD4` | `0x450FD4` |
| 追加敵レコードからの呼出し | `0x5514F4` | `0x4514F4` |

基礎経験値は
`data/res/character/chara_param_0.03a.cfg.bin`の`CHARA_PARAM_INFO`にあります。
CFGでは0始まりの値番号34、行の開始位置を `R` としたときの `R + 0x9C`、ランタイムの
キャラクターパラメータ構造体では `+0x6A` の16ビット符号なし整数です。

`sub_55549C` は `B > 100`、`B <= 80`、`81 <= B <= 100` を
`0x5554A4`〜`0x5554D8`で分岐し、`0x5554F0`で正の浮動小数点数を整数へ切り捨てます。
敵レコード `+0x13C == 2` の特殊扱いでは、基礎経験値をそのまま返します。

ボー坊の内部IDは `y161000` です。`chara_param_0.03a.cfg.bin`の
`CHARA_PARAM_INFO` index 148、ファイルオフセット `0x8554` に対応し、モデルハッシュは
`0x90B8AFA3`、基礎経験値は81です。

### さすらい玉の出現判定

有効な攻撃や妖術などが1件処理されるたびに、`battle + 0x5E3C` が1増えます。

```text
0x54F2B4  LDR R0, [battle + 0x5E3C]
0x54F2B8  ADD R0, R0, #1
0x54F2BC  STR R0, [battle + 0x5E3C]
0x54F2C4  BL  sub_552AB4
```

`sub_552AB4` はこの値が6の倍数のときだけ、通常の出現抽選へ進みます。各回の確率は
次の回数補正と、両陣営の平均レベル差による補正の合計です。

| 有効な戦闘イベント数 | 回数補正 |
| ---: | ---: |
| 6 | 5% |
| 12 | 5% |
| 18 | 10% |
| 24 | 15% |
| 30 | 20% |
| 36 | 25% |
| 42 | 30% |
| 48 | 35% |
| 54以上 | 40% |

平均レベル差の補正は、内部の2陣営を比較して差が5以上なら10%、0〜4なら5%、
-1以下なら0%です。回数の読出しは `0x552C68`、6の倍数判定は
`0x552C74`〜`0x552C8C`、補正の加算と乱数比較は `0x552CAC`〜`0x552D2C` にあります。

さすらい玉の種類が決まると、`0x552F0C` でカテゴリが `battle + 0x5DFC` に保存されます。
以後は `0x552AF8`〜`0x552B00` の検査で抽選処理を通らないため、同じ戦闘中に次の
さすらい玉は選ばれません。

経験値カテゴリが選ばれた場合は、通常型が2倍、10%で選ばれる強い型が3倍です。

| 設定 | バトル変数ID | 値 |
| --- | --- | ---: |
| 強い型の選択率 | `0xD09034FA` | 10% |
| 通常型の倍率 | `0x6E58CF33` | 2.0 |
| 強い型の倍率 | `0x8E656886` | 3.0 |

カテゴリの候補追加は `0x552E2C`〜`0x552E38`、候補選択は
`0x552E9C`〜`0x552EB0`、経験値への倍率適用は `0x551B1C`〜`0x551B9C` です。

### 戦闘結果の合成

戦闘結果を組み立てる関数は `sub_550D64` です。

| 結果構造体 | 内容 | 根拠アドレス |
| ---: | --- | ---: |
| `+0x10` | 敵ごとの通常経験値の合計 | `0x550FE8`、`0x551508` |
| `+0x1C` | 味方6枠の戦闘内イベント経験値 | `0x551AD0`〜`0x551B10` |
| `+0x14` | 経験値さすらい玉などによる差分 | `0x551B18`〜`0x551B9C` |
| `+0x20` | 戦闘状態ビット `0x40000` による20%加算 | `0x551BA0`〜`0x551C00` |
| `+0x0C` | 最終経験値 | `0x551C2C` |

```text
finalExp = result[+0x10] + result[+0x1C]
         + result[+0x14] + result[+0x20]
```

戦闘状態ビット `0x40000` が立っている場合は、通常経験値と戦闘内イベント経験値の
小計へ20%が加わります。倍率はバトル変数 `0xEDF91C92` の1.2です。このビットを立てる
条件は特定できておらず、戦闘時間との対応もありません。

戦闘内イベント経験値は、各味方妖怪の状態構造体 `+0x49C` に保持されます。加算関数は
`sub_572194`、唯一の呼出しは `0x5805F0`、イベント種別は17、加算値の読出し位置は
イベント構造体 `+0x4C` です。標準の戦闘終了処理が作る種別17では加算値が0になります。
非ゼロ値を設定する経路は特定できていないため、この欄をおはらいまたは長期戦による経験値と
断定することはできません。
