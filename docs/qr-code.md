# 非公式のQRコードが読み込める理由

## 概要

QRコードの発行元を調べているのではなく、読み取った文字列に正しい認証値が付いているかを
確認しています。認証値を作るための鍵はゲーム本体に入っているため、同じ計算方法で文字列を
作れば、公式が発行していないQRコードでも読み取れます。

報酬はコード本体の先頭部分で選ばれ、同じ報酬に当たる先頭部分が複数あります。
一部の特別なコードを除き、残り4文字を変えても報酬は同じです。先頭部分1通りにつき
最大167万9616通りの異なるQRコードを作れます。このため、同じ報酬のQRコードを
大量に作れます。

作れる報酬はゲーム内の設定表にあるものに限られ、QRコードの文字列へ好きなアイテムIDを
直接書き込むことはできません。

ただし、英数字を適当に並べたQRコードが通るわけではありません。コード本体の後ろに、
その内容に対応した26文字の認証値が必要です。

## 内部処理

### データ形式

読み取り結果の最後の `/` より後ろが、次のどちらかの形式なら検証対象になります。

| 種類 | コード本体 | 認証値 | 合計 |
| --- | --- | --- | ---: |
| QR1 | 報酬番号2文字＋区別用4文字 | 26文字 | 32文字 |
| QR2 | 報酬番号3文字＋区別用4文字 | 26文字 | 33文字 |

コード本体の文字は `0`〜`9`・`A`〜`Z` に限られます。

`sub_3AFBA4` の `0x3AFBC8`〜`0x3AFBEC` は最後の `/` を探し、
`0x3AFC30`〜`0x3AFC3C` で後続部分の長さを分けます。コード本体の英数字を
`0x3AFCA0`〜`0x3AFCC4` または `0x3AFCF8`〜`0x3AFD1C` で確認し、残りの
26文字を認証値として取り出します。`/` より前の文字列は認証計算に使われず、
特定のドメイン名との比較もありません。

### 認証値の計算

| 種類 | 1回目の鍵 | 2回目の鍵 |
| --- | --- | --- |
| QR1 | `A14+BDM71D` | `QK35+NI8WV` |
| QR2 | `OYD78+MIP3` | `N+Q09V7LI5` |

`0x7025FC` の表が種類ごとの長さ・鍵・認証値の長さ26を保持しています。
`sub_3AFD48` はコード本体に対して1回目の鍵でHMAC-MD5を計算し、得た16バイトを
小文字の16進数32文字に変換します。その**文字列**に2回目の鍵でHMAC-MD5を計算し、
結果の16バイトを5ビットずつ区切り、次の32文字を使う独自のBase32形式に変換します。

```text
GN5BH8QJSAC0MFR6P4VET1O7K9U2LD3I
```

最後に残る3ビットは0を補って5ビットにせず、その値をそのまま26文字目の文字番号に
します。この処理は `sub_5C603C` の `0x5C6110`〜`0x5C6124` にあります。

変換後の26文字と、QRコードから取り出した認証値が一致すると認証に成功します。
比較は `0x3AFE60`〜`0x3AFE78` です。HMAC-MD5の計算は `sub_4A23BC`、
小文字の16進数への変換は `sub_4E66E8`、Base32形式への変換は `sub_4C1834` が
担当します。例えばQR1のコード本体 `000000` に対する認証値は
`F72NN8N4OGBPP33KUG85FGP54G` です。

読み取り処理 `sub_5DBD78` は `0x5DBE0C` でこの検証を呼びます。検証関数
`sub_3AF84C` は認証値が一致した場合だけコード本体と種類を結果に残します。
固定鍵を持つ本体内の計算で判定するため、この段階では公式の発行履歴と照合しません。

### 報酬の設定

`data/res/qr/qr_config_0.04b.cfg.bin` には `QR1_INFO` が302件、`QR2_INFO` が
382件あります。各項目は番号範囲の下限・上限とアイテムIDからなります。例えば
`QR1_INFO` の先頭項目は `0`〜`2` と `0x9A89BF7C`、`QR2_INFO` の先頭項目は
`0`〜`9` と `0x35F5616A` です。両IDは
`data/res/item/item_config_0.04b.cfg.bin` の `ITEM_CONSUME` と `ITEM_INDEX` にも
存在します。

認証後の `sub_3AF92C` は `0x3AF9CC`〜`0x3AFA24` でQR1なら先頭2文字、QR2なら
先頭3文字を `sub_3AFB10` で36進数の番号に変え、`sub_63B048` に渡します。
`sub_63B048` の `0x63B06C`〜`0x63B0A0` はその番号を設定表の範囲と照合して
アイテムIDを返します。該当範囲がない場合は `QR1_RAND_INFO` または
`QR2_RAND_INFO` の重みに従って候補を選びます。

両形式の設定表に現れるアイテムIDは合計38種類です。残り4文字には `0`〜`9`・
`A`〜`Z` を使えます。この4文字は報酬の範囲検索には使われませんが、認証値の計算と、
`sub_3AF92C` の `0x3AF998`〜`0x3AF9C8` にある読み取り済みコード本体との照合に
使われます。同じ報酬番号でも、この4文字が違えば別のコードになります。

例外として、QR1の `P1ZZZZ` は `0x3AF968`〜`0x3AF994` で個別に判定され、通常の
報酬検索には進みません。
